The resident doomer群里的厌世老哥

A DeepSeek-powered chat bot that lives in our server. It's tired, pessimistic and short-spoken, jumps into chats now and then, reads files and links you give it, and writes a recap every night. 一个由 DeepSeek 驱动、住在我们服务器里的聊天 bot。它很丧、很悲观、话很少，偶尔自己插话，能读你给它的文件和链接，每晚写一篇总结。

> you: @deepseekbot how's your day
> bot: started bad, peaked at bad. thanks for asking i guess开局很烂，巅峰也很烂。谢谢关心吧

Daily reply budget每日回复余额

  • 50 replies a day, shared by everyone: mention replies, jump-ins and file/link replies all count.每天 50 条，所有人共用：@ 回复、主动插话、读文件和链接的回复都算。
  • Refills every morning at 09:00 Adelaide time.每天早上 09:00（阿德莱德时间）恢复满。
  • When it runs dry, the next person who mentions it gets one "out of juice" message, then silence until the refill.用完后，下一个 @ 它的人会收到一句“没电了”，之后它就安静到恢复为止。
  • Kurt's messages and /rule don't use the budget. Kurt can refill it early with /feed.Kurt 的消息和 /rule 不扣余额。Kurt 可以用 /feed 提前补满。

Every day每天的固定节目

22:00 · nightly recap22:00 · 每晚总结

It reads the last 24 hours of human messages in every channel it can see and posts up to 5 bullet points, in English and in character. It uses names only and doesn't @ anyone.读它能看到的所有频道最近 24 小时里真人的消息，用英语、按人设口吻发最多 5 条要点，只写名字，不 @ 任何人。

Three conversation starters (at least two of them weird) picked from news, tech, CG, AI, Australian news, GitHub trending and a few subreddits, plus one gloomy life thought. Links don't unfold into big previews.从新闻、科技、CG、AI、澳洲本地新闻、GitHub 热门和几个 Reddit 版块里挑 3 个话题（至少 2 个怪话题），再加 1 句丧气的人生感悟。链接不会展开大预览。

If Kurt's computer is off at those times, that day is simply skipped.如果那时 Kurt 的电脑没开，当天就跳过。

Privacy隐私

  • Messages it reads (yours, the recap's, file and link contents) are sent to the DeepSeek API to generate replies.它读到的内容（你的消息、总结用到的聊天、文件和链接的内容）会发给 DeepSeek API 来生成回复。
  • On Kurt's computer it keeps only a short group profile (interests, running jokes) and the last 10 recaps. Raw chat is never saved.Kurt 电脑上只存一份简短的群档案（兴趣、常驻梗）和最近 10 篇总结，聊天原文从不保存。
  • Don't want a channel read? Remove the bot's permission to view it.不想某个频道被读？去掉 bot 查看那个频道的权限就行。
  • Don't paste passwords or keys anywhere it can see.别在它看得到的地方贴密码或密钥。

The one floor唯一的底线

Swearing and roasting are fine. It won't do slurs or hate against groups, doxxing or real threats. If someone seems genuinely in a bad place, it drops the bit and acts like a decent friend.骂人和互怼都可以。它不会说针对群体的仇恨言论，不会人肉，不会真的威胁人。如果有人看起来真的状态很差，它会放下人设，像个正常朋友一样关心对方。

Architecture架构

Four containers from one image (plus the proxy). The two that hold secrets can only talk to Discord and DeepSeek. The one that browses the web holds no secrets.四个容器，三个程序共用一个镜像，另加一个代理。拿着密钥的两个只能连 Discord 和 DeepSeek；能上网的那个手里没有任何密钥。

Control flows one way: Kurt's phone → Claude Code on the PC → docker compose → containers. Nothing inside a container can reach back to the PC, the LAN or Claude.控制方向是单向的：Kurt 的手机 → 电脑上的 Claude Code → docker compose → 容器。容器里的东西碰不到电脑、局域网或 Claude。

Isolation隔离

  • Every container: read-only filesystem, non-root user, all Linux capabilities dropped, no-new-privileges, memory/CPU/process limits, no published ports, no Docker socket.每个容器：只读文件系统、非 root 用户、去掉全部 Linux capabilities、no-new-privileges、内存/CPU/进程数上限、不对外开端口、不挂 Docker socket。
  • The containers sit on an internal network with no route out and no host-side gateway. The only way out is the Squid proxy.容器在一张没有出网路由、也没有主机侧网关的内部网络上，唯一的出口是 Squid 代理。
  • Squid tells containers apart by fixed address: bot and scheduler may reach Discord and api.deepseek.com only; the fetcher may reach any public site. Private, loopback and link-local addresses are refused after DNS for everyone, so nothing can reach the PC or the home network.Squid 按固定地址区分容器：bot 和 scheduler 只能连 Discord 和 api.deepseek.com；fetcher 能连任何公网网站。私网、回环和链路本地地址在 DNS 解析后一律拒绝，所以谁都碰不到电脑或家里的网络。
  • All file parsing happens in the fetcher, which has no secrets and refuses to start if one is passed in. A malicious PDF can't get at the tokens.所有文件解析都在 fetcher 里做；它没有任何密钥，如果被传入密钥会拒绝启动。恶意 PDF 拿不到 token。
  • The only mount in the whole stack is a data folder for the scheduler.整套系统唯一的挂载，是给 scheduler 用的 data 文件夹。
  • The model has no tools. Chat, files, pages and headlines are fetched by code and handed to it as untrusted data, so a prompt injection can at worst make it say something dumb.模型没有工具。聊天、文件、网页和新闻标题都由代码取来，作为不可信数据交给它，所以提示词注入最坏也只能让它说句蠢话。

Flows流程

Mention reply@ 回复

  1. Gateway event → skip bots, blocked channels and non-owner DMs.收到 gateway 事件 → 跳过 bot、屏蔽频道和非 Kurt 的私信。
  2. Spend one unit of budget (unless it's Kurt).扣 1 条余额（Kurt 不扣）。
  3. Attachments and links go to the fetcher, which returns plain text.附件和链接交给 fetcher，拿回纯文本。
  4. Build context: reply chain first, then recent channel history, 12 messages max.组装上下文：回复链优先，再补频道最近的消息，最多 12 条。
  5. One chat completion with the persona. A <<<FILE name.md>>> block in the answer becomes an attachment.带人设调用一次对话补全。回答里如果有 <<<FILE name.md>>> 块，就变成附件发出。
  6. If the model call fails or it answers nothing, the budget unit is refunded.模型调用失败或没有回答时，余额退回。

Jump-in主动插话

  1. Each human message updates a per-channel window; a 3% roll (5% for Houdini/FX talk) or more than 12 messages in 3 minutes triggers, unless the channel is cooling down.每条真人消息更新该频道的时间窗口；3% 随机命中（Houdini/FX 话题 5%），或 3 分钟内超过 12 条就触发，冷却期间除外。
  2. The model sees the last 12 messages numbered and answers REPLY_TO: n plus its message, or SKIP (refunded).模型看到编号的最近 12 条消息，回答 REPLY_TO: n 加上它的话，或者回答 SKIP（退回余额）。
  3. Sent as a Discord reply to message n with the reply ping switched off; the channel cools down for 10 minutes.以 Discord 回复的形式接在第 n 条下面，关掉回复提醒；该频道冷却 10 分钟。

Nightly recap (22:00)每晚总结（22:00）

  1. Read 24 h of human messages from every visible channel over the REST API.通过 REST API 读所有可见频道 24 小时内的真人消息。
  2. If it's longer than ~60k characters, compress it chunk by chunk first.超过约 6 万字就先分段压缩。
  3. Write the recap using the last 3 recaps and the group profile as context; post it; save it (kept 10 days).参照最近 3 篇总结和群档案写总结；发出去；存到本地（保留 10 天）。
  4. Rewrite the group profile with today merged in; topics nobody mentions fade out. Kurt's hand-written section at the top is never touched.把今天的内容并进群档案重写一遍，没人再提的话题慢慢淡出。顶部 Kurt 手写的部分从不改动。

Morning topics (08:00 → 09:00)早上话题（08:00 → 09:00）

  1. 08:00: the fetcher pulls ~12 RSS feeds and two combined Reddit RSS feeds; results are cached locally.08:00：fetcher 抓约 12 个 RSS 源和 2 个合并的 Reddit RSS，结果缓存在本地。
  2. 08:30: retry only the feeds that came back empty, politely spaced.08:30：只补抓空掉的源，请求之间留出间隔。
  3. 09:00: the model weighs the headlines against the group profile and picks 3 topics (≥2 weird) plus a life thought. The cache is deleted after posting.09:00：模型对照群档案权衡这些标题，挑 3 个话题（至少 2 个怪话题）加一句人生感悟。发完后删除缓存。
